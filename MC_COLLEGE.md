# Montgomery Community College – Varbase + Educare build

Drupal 11.4 · Varbase 11.0 · Educare 1.0 site template · DDEV

## Prerequisites

- WSL2 Ubuntu with Docker and DDEV (`ddev --version`)
- This project at `~/projects/montgomery-college` (keep it on the Linux filesystem, not `/mnt/c` or `/mnt/i`)

## Build from scratch

```bash
# 1. Project + site template
ddev config --project-type=drupal11 --docroot=web --php-version=8.4 --project-name=montgomery-college
ddev config --web-environment-add=DRUPAL_CMS_TELEMETRY=0
ddev start
ddev composer create-project "drupal/varbase_project:~11.0.0"
ddev composer require "drupal/educare:~1.0.0"
ddev drush site:install ../recipes/educare -y --site-name="Montgomery Community College"

# 2. Enrollment and financial modules
ddev composer require \
  "drupal/registration:^3.4" \
  "drupal/commerce_registration:^3.4" \
  "drupal/commerce_invoice:^2.3" \
  "drupal/multiple_registration:^3.4" \
  "drupal/academic_marksheet:^1.0" \
  "drupal/computed_field:^4.0" \
  "drupal/charts:^5.2" \
  "drupal/eca:^3.1"
ddev drush en registration commerce_registration commerce_invoice multiple_registration academic_marksheet computed_field charts eca -y

# 3. Generate the recipe and theme (mc_college_core, mc_college_billing, and
#    scripts/*.php are maintained as source files in the repository)
bash setup_blueprint.sh

# 4. Apply the recipe (Drush 13 has no `recipe` command; use core's runner)
ddev drush cr
ddev exec php bin/dr recipe /var/www/html/recipes/mc_college_structure
ddev drush updb -y

# 5. Tuition billing (store, USD, term bills, Bursar gateway and role)
ddev drush en mc_college_billing -y

# 6. Theme
ddev drush theme:enable mc_college
ddev drush config:set system.theme default mc_college -y
ddev drush cr

# 7. Seed content: 5,000 nodes, sessions, 60 students with 4 semesters of history
ddev drush php:script scripts/mc_seed.php
#   ddev drush php:script scripts/mc_seed.php -- --sessions=500 --students=100
#   ddev drush php:script scripts/mc_seed.php -- --force     # add another batch
ddev drush php:script scripts/mc_seed_billing.php           # bills + sample payments

# 8. Finish
ddev drush cr
ddev drush php:eval 'node_access_rebuild();'
ddev drush cron
ddev drush sql:query "SELECT type, COUNT(*) FROM node_field_data GROUP BY type ORDER BY 2 DESC;"
```

## Academic rules

- **GPA**: A=4, B=3, C=2, D=1, F=0, credit-weighted, Completed registrations only. P earns credit (no GPA);
  I is attempted (no credit, no GPA); W is attempted (no credit, no GPA). Term and cumulative GPA on transcripts.
- **Standing**: probation below 2.00 cumulative; Dean's List at 3.50+ term GPA with 6+ graded credits (configurable).
- **Add / drop / withdraw** (per semester dates): Drop through the Drop Deadline (no transcript entry, no tuition);
  Withdraw through the Withdraw Deadline (W, tuition still owed); after that, Registrar only.
- **Non-matriculated students**: at most 11 credits per semester; must matriculate after earning 12 credits
  (registration blocked until they do); cannot self-register for sessions marked "Restricted to Matriculated".
- **Enrollment status**: only Active students can register.

## Tuition and fees

- One bill (Commerce order, type *Term bill*) per student per semester, numbered when created.
- Tuition = credits × per-credit rate for the student's residency; plus a per-credit technology fee and flat
  per-term fees. **Rates are placeholders** (In-District $130, Out-of-District $270, Out-of-State $370 per
  credit; $15/credit technology; $25 registration; $40 student activity) — set the real schedule at
  `/admin/commerce/config/tuition`.
- Bills recalculate automatically when a student adds, drops, or withdraws, or when residency changes.
  Payments are kept. After changing rates, run `scripts/mc_seed_billing.php -- --no-payments` to re-bill.
- Payments: the Bursar records them on the bill (**Payments → Add payment**, gateway *Bursar's Office*).
  Online card payments need a real payment gateway module (e.g. Stripe), which has not been chosen.
- Optional **financial hold** blocks new registrations while an earlier semester has an unpaid balance.

### Content model

Educare already provides **Program**, **Event**, and **News**; the recipe adds fields to Program and reuses
Educare's `field_location`. New types:

| Type | Fields |
|---|---|
| Course | Description, Course Code, Credits, Department |
| Course Session | Course, Semester, Professor (user with Professor role), Meeting Date/Time (date range), Location, Capacity, Restricted to Matriculated, Registration |
| Semester | Start/End Date, Registration Opens/Closes, Drop Deadline, Withdraw Deadline |
| Faculty Profile | Biography, Position, Department, Email, Phone, Office, Photo (media) |
| Scholarship | Description, Award Amount, Deadline, Department, Application URL |
| Program (Educare) | + Department, Program Level, Credits |
| User | Student Type, Student ID, Program of Study, Residency, **Cumulative GPA** (computed) |
| Registration (course_session) | **Grade** (A, B, C, D, F, P, I) |

Vocabularies: **Department**, **Program Level** (Educare's own vocabularies are left untouched).

### Registration workflow (`course_registration`)

| State | Holds a seat | Meaning |
|---|---|---|
| Enrolled | yes | Default for new registrations |
| Waitlisted | no | Held; promote with *Enroll* |
| Completed | yes | Grade counts toward GPA |
| Dropped | no | Before the drop deadline |
| Withdrawn | no | After the drop deadline |

Transitions: Enroll (Waitlisted → Enrolled), Move to waitlist, Complete, Drop, Withdraw.
Seat counts come from each session's registration settings (the seed sets them to the session's Capacity).

### GPA

`field_gpa` on user accounts is a computed field (plugin `mc_college_student_gpa`):
credit-weighted average of A=4, B=3, C=2, D=1, F=0 over **Completed** registrations, using each
course's Credits. P and I grades and non-completed registrations are excluded. Nothing is stored;
the value is recalculated when registrations or content change.

### Roles and access

| Role | Can |
|---|---|
| Student | Self-register for sessions (not restricted ones unless matriculated); view own registrations and grades |
| Professor | For sessions where they are the Professor only: view the roster, change registration state, enter grades |
| Registrar | Administer all course registrations and settings, edit user accounts, view/administer orders |

Student record fields (type, ID, program, residency, GPA) are visible only to the student and user
administrators, and editable only by user administrators. These rules live in
`mc_college_core/src/Hook/McCollegeCoreHooks.php`.

## Not automated (needs decisions)

- **Online payments:** choose a payment gateway (Stripe, PayPal, Authorize.Net, …) and install its
  Commerce module; bills already carry balances, so a "Pay online" checkout can be added on top.
- **Real tuition schedule:** the rates in `mc_college_billing.settings` are placeholders.
- **Payment plans:** `commerce_installments` has no Drupal 11 release; installment plans would need a
  custom solution or a different module.
- **Registrar overrides of deadlines:** registrars can change any registration state at any time through
  the registration edit form; there is no separate audit log beyond Drupal's revision/log entries.
- **Front-page hero:** the home page is a Canvas page; edit it at `/home` with the Canvas editor.
- **Canvas templates for the college types:** Varbase auto-creates an empty Canvas "full" template and
  a bare "full" view display for every new content type, which would render blank pages.
  `mc_college_core` saves those disabled, so Course, Course Session, Semester, Faculty Profile, and
  Scholarship pages use the recipe's default display. To design them in Canvas, build the template
  at `/admin/structure/types/manage/<type>` and enable it.
- **Faculty profile ↔ user account link:** sessions reference Professor *users*; profiles are
  separate public pages.
- `commerce_installments` was not installed: its only release supports Drupal 8.
